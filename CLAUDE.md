# SenAI Watermark Remover

Cleans SenAI Maths PDFs:
- replaces the "SenAI Maths" title on page 1 with "Brinns autocompleter",
  which is the only text it adds;
- removes the `senai.uk` footer on every page;
- fixes SenAI's typesetting faults (empty boxes for missing symbols, and
  sentences set with no spaces).

A Windows desktop app (Qt, four themes) plus a command line. Users are
students on Windows who run the single-file `.exe`; keep wording plain and
friendly.

## Commands

```bash
pip install -e ".[gui,test]" pyflakes        # the SessionStart hook does this in cloud sessions
QT_QPA_PLATFORM=offscreen python3 -m pytest -q   # ~112 tests, ~8 s
python3 -m pyflakes senai_remover tests tools    # the linter; keep it clean
python3 tools/screenshots.py OUT_DIR [1-4]       # every theme × light/dark × empty/listed/done
python3 tools/screenshots.py --previews          # Settings card images → senai_remover/gui/assets/previews/
python3 tools/screenshots.py --docs              # README images → docs/screenshots/
python3 tools/make_icon.py                       # app.png + app.ico (needs Pillow)
python3 tools/make_version_info.py build/version_info.txt   # .exe details for PyInstaller --version-file
NODE_PATH=$(npm root -g) node tests/fixtures/make_maths_sample.cjs   # the repair test PDF
```

Always look at screenshots (Read the PNGs) after any visual change, in light
and dark. Regenerate `--previews` and `--docs` when a theme's look changes.

## Layout

- `senai_remover/core.py`: the PDF cleaner. Decodes each text object (BT…ET)
  through the font's ToUnicode CMap, matches `DEFAULT_PATTERNS`, and deletes only
  the text-showing operators that draw a match. If deleting would shift other
  text on the same line, the run is hidden with render mode 3 instead. It also:
  - strips senai.uk links and matching metadata;
  - draws the new title (`DEFAULT_TITLE`) where the old one started, in a
    standard font of the same style;
  - sets the document title to the file name;
  - owns output naming (`DEFAULT_NAME` "{name}-clean", `name_problem`).
- `senai_remover/repair.py`: the typesetting repairs. Classifies each `.notdef`
  glyph by ActualText, superscript position or operator spacing (° · ⟹), and
  re-sets run-together maths-italic sentences after splitting them with the
  word list. It reuses the PDF's own fonts where they have the glyphs. A line
  it can't read confidently is left alone; keep it that way.
- `senai_remover/pdftext.py`: the glyph walker (position, size, font, colour,
  CTM per glyph). It also provides `remove_glyphs`, which keeps the pen
  position, and `draw`, which inserts replacement text in reading order.
- `senai_remover/_words.py` and `_metrics.py`: generated data (by
  `tools/make_words.py` and `tools/make_metrics.py`). Don't edit them by hand.
- `senai_remover/cli.py`: `senai-remover`. Needs only pypdf, never Qt.
- `senai_remover/gui/`:
  - `model.py`: Qt-free state: the session, job statuses, the output-name plan,
    and every user-facing message (`friendly_error`, `RunSummary.text`).
    Put wording here, not in themes.
  - `controller.py`: the Qt list model plus a QThread worker. The controller
    outlives windows.
  - `app.py`: `Shell` rebuilds the window when the theme or appearance changes,
    keeping the controller.
  - `settings.py` / `settings_panel.py`: the saved theme, appearance and
    output name (an INI via QSettings; `SENAI_SETTINGS_FILE` overrides it),
    and the slide-in settings bar. Theme wording that mentions the output
    name goes through `BaseWindow.naming()` so it follows the setting.
  - `theme.py`: fonts, Lucide icons, the WCAG contrast maths, and Windows
    system preferences.
  - `widgets.py`: shared widgets and the `Labels` class (title case for the
    Apple themes, sentence case for the others).
  - `designs/`: `base.py` holds all shared behaviour (commands, shortcuts,
    drag and drop, menus, settings). Each theme file only builds widgets and
    paints.
- `tests/`: `test_core`, `test_repair`, `test_cli`, `test_gui_model`, and
  `test_gui`. The last one drives every theme offscreen and checks contrast.
  `tests/fixtures/maths_sample.pdf` (from `make_maths_sample.cjs`) reproduces
  SenAI's typesetting faults: Chrome with only the Liberation fonts. The fixture
  `tests/fixtures/senai_sample.pdf` is generated by `make_sample.cjs`. Never
  commit users' real PDFs.

## Themes

Each theme is a `BaseWindow` subclass. It defines:
- `ID`, `NAME`, `DESCRIPTION` and `TITLE_CASE`
- `LIGHT`/`DARK` token dicts. They must include `bg`, `surface`, `border`,
  `separator`, `label`, `secondary`, `disabled`, `accent`, `on_accent`,
  `accent_text`, `success`, `warning` and `danger`.
- `CONTRAST`, a list of (text, background, minimum) pairs
- `tokens(prefs)`, `stylesheet(t)` and a `RowDelegate`
- `build()`, which must set `self.t` and `self.list_view`, plus a visible gear
  from `self.settings_button(...)`

To add a theme, register it in `designs/__init__.py`, then run `--previews`.
The tests pick it up automatically.

Rules the tests enforce or that reviews expect:
- **Contrast:** every declared text pair is at least 4.5:1, in light, dark and
  high contrast. That includes the settings bar on the theme's `surface`.
- **Status:** never shown by colour alone. Icons always come with words.
- **Keyboard:** focus is visible on every control, and icon-only buttons have
  tooltips and accessible names (`icon_button`).
- **Apple themes:** follow `.claude/skills/apple-design` (Apple's HIG).
- **Fonts and icons:** Inter is bundled under the OFL. Icons come from
  `lucide-static@1.61.0` on unpkg, with the first comment line stripped; keep
  `assets/icons/LICENSE`.

## Windows build and Qt version

- PySide6 is pinned to `>=6.8,<6.9`. Qt 6.9+ needs Windows' system `icuuc.dll`,
  which Wine lacks, and Wine is how the `.exe` gets tested here.
- The PyInstaller command is in README → Building the Windows .exe. Run it with
  `--add-data` for `senai_remover/gui/assets`.
- The `.exe` carries its product name and version (`tools/make_version_info.py`
  → `--version-file`). SignPath Foundation's free code signing needs them, plus
  the MIT `LICENSE` and the README's "Code signing policy" section; keep all three.
- The `/build-exe` skill builds and smoke-tests the `.exe` under Wine in a cloud
  session.

## Releases

1. Bump `senai_remover/__init__.py` `__version__`.
2. Add a `## [X.Y.Z] - date` section at the top of `CHANGELOG.md`. The Release
   workflow uses that section as the release notes.
3. Merge the PR, then run Actions → Release → Run workflow (`all`, or the
   new tag).

`.github/workflows/release.yml` builds and publishes the release:
- **Tags:** it tags any version that has no tag yet, at the first commit on
  `main` that has that version (the release PR's merge).
- **Notes and Latest:** it takes the release notes from the changelog and
  marks the newest version as Latest.
- **Re-running:** safe; it replaces the notes and the `.exe` on existing
  releases.
- **Asset name:** always `SenAI-Watermark-Remover.exe`, so
  `/releases/latest/download/SenAI-Watermark-Remover.exe` keeps working.

Claude cloud sessions can push branches but **not tags** (HTTP 403), so let
the workflow create them.

## GitHub notes

- **Public repo:** the repo is public, so Actions on GitHub-hosted runners
  costs nothing. v1.0.0, v2.0.0 and v2.1.0 were published by the Release
  workflow on 21 Oct 2026.
- **Starting the release:** Claude can start it with the GitHub MCP tool
  `actions_run_trigger`: `run_workflow`, `release.yml`, ref `main`, inputs
  `{"tags": "all"}` or `{"tags": "vX.Y.Z"}`.
- **No release API:** Claude's GitHub tools can't create releases or upload
  assets themselves, so releases always come from the workflow.
- **Runs that never start:** if a run fails before any job starts, or a job
  has no runner, read the job's annotations. They give the reason, for example
  "account is locked due to a billing issue", which only the owner can fix:
  `https://api.github.com/repos/ImBrinn/Senai-watermark-remover/check-runs/<job id>/annotations`.
